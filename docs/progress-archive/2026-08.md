## 2026-08-27 — Turnstile language remount, blog skeleton parity, first pass at five product loop animations, device disconnect/rearrange

**Summary**: Four unrelated fixes on the homepage and registration page, found by walking through the reported symptoms rather than guessing at causes.

Registration Turnstile failed after a language switch because the widget's `options.language` was hardcoded to `zh-TW` and nothing reset it when `language` changed. `Turnstile` took `key={language}` (forces a clean remount), `options.theme` became `'auto'`, `options.language` followed `language`, and both `onError` and the failed-verify branch reset the widget and cleared the stored token.

The homepage blog rail's loading skeleton wasn't shaped like the real cards it gets replaced by, so the swap-in was a layout jump. Skeleton was made to share the exact card shell and scroll-driven positioning — later found to be an incomplete fix; see the follow-up session below, which removed `.blog-berth`'s horizontal entrance drift entirely.

Five of six `HeroIllustration` product-screen loops (news, game, social, youtube; chat was already built) got a first-pass design: scrolling list rows for news, a patrolling dot for game, a 3-post feed + heart burst for social, a play button + progress bar for youtube. All were percentage-transform SVG groups missing `transform-box: fill-box`. This first pass was scrapped and redesigned bolder in the next session — the list rows, patrol dot and scrolling feed read as static/illegible at the size these devices actually render.

Product phones/tablets became clickable, toggling connected state. First pass: the outer device dimmed/grayscaled in place and showed a "no signal" X icon when off. Corrected in the next session — the device is the source, not a mirror, so disconnecting it should never change its own screen, only its tile on the monitor.

## 2026-08-24 — page-wide motion system

## 2026-08-24 — harbour plate rigidity and hero submersion

Four sessions, all on the homepage hero.

**Plate made rigid.** The plate was not pinned, because a CSS `transform` in px means viewBox user units on an SVG element and CSS px on the canvas. Both got `translateY(-69.3252px)` and travelled 82.93px vs 69.33px, exactly the 1.1963 viewBox scale apart, so the waterline climbed the buildings ~14px per scroll. Fixed by expressing the travel as a fraction of the scene: 68.4 of 760 viewBox units for SVG members, the same distance in `cqw` for the canvas. Separately, `VesselWaves` sat outside `hk-vessel-sail` / `hk-bob`, so hulls slid up to 22 user units off their own ripples; the ripples moved inside the bob group and `HarbourWater` reads the live sail matrix off the DOM each frame for the canvas reflections.

**Plate is one HTML transform.** Matching units still left members moving independently, so the lift moved to `.hero-pin-city`, the HTML wrapper holding both the SVG and the canvas — real CSS pixels the viewBox scale cannot multiply unevenly. Canvas vessel-foam dashes, remapped from `mapSvgY` on every scroll, were the remaining unlocked ripples and were deleted. Measured drift 0.00px at `--p-depth` 0.917.

**Waterline continued below the scene.** The climbing water column fogged the city from the bottom with `--bg-base`. The real defect was behind the scene: the mask wipes the bottom ~24vh and the page showed through, and navy water against neutral `#0b0f14` read as a cut. `.hero-deep-water` now sits behind the mask carrying the water's own two tones down, travelling 30vh against the plate's 7vh so the depth gradient sweeps up through the frame.

**Hero submersion and heading reveals.** Removed the teal `hero-scene-horizon` and the tonal step under it. `--p-mask` starts at 0.32 instead of 0.48. Headings climb out from behind a mask (`.scrub-reveal` / `.scrub-word-mask`, 112% travel) instead of fading, and `SectionHeading`'s h2 lost its own `scrub-title` because block rise plus per-word rise averaged into a soft fade.

## 2026-08-25 — load entrance, product identity slot

`Scrub` could not animate a section that was already on screen when it mounted. `--p` is derived purely from scroll distance, so a section whose top sits below `vh * 0.52` reads 0 and stays there until the reader scrolls — on a tall viewport that left `/services` showing a blank band with one orphan hairline where "我們提供什麼" and the practice index should be. Sections visible at mount now run their entrance on a clock instead: a 1.1s ease-out ramp after a 160ms lead, held by a floor that only ever climbs, so the scroll value takes over without a step back. ## 2026-08-25 — seamless draws, brand colour, hero contents, icon set

The quote drawings on `/services` hitched, and it was not frame rate — sampled over the section they run 8.4ms median, 10.1ms p95, nothing over 20ms. It was the opacity track: `--gd` staggers each stroke by up to 0.4s, so the three lines faded out one after another over a 1.16s window and the glyph came apart a line at a time on the way out. They now carry a dash *and gap* each the length of the path, so the offset runs 1 → 0 → -1 and the stroke wipes out in the direction it was written. Both ends of the cycle are blank, so any stagger loops without a seam and the opacity track is gone. Seal and tick moved into one group with a shared fade, since separately timed the tick outlived the disc it sits on.

Colour on the product diagrams follows one rule now: whatever carries the action is signal, whatever holds still around it stays muted. The focused pane is brand and the three it displaced are not; where the whole diagram is the action — the device grid, the closing capture frame — all of it is. That gives the index loud and quiet rows instead of six uniform ones, and it applies to the install drawings too.

The install line ends. It reached the last step and ran out of page, which read as a line cut off rather than one that finished, so it takes a filled terminus — round, where the four stops are ticks, so it cannot be read as a fifth. The numeral also moved above the drawing: it names the stop, and it was sitting two rows below the tick it belongs to.

`/services` hero: under the rule was 3.5rem of nothing. It now carries the page's contents — the six practices, each opening its own entry in the index below and taking the reader there. Live buttons, not labels, because a row of six names that looks clickable and is not would be worse than the empty band.

The two case studies with no write-up are articles now, not links to unrelated routes, and they lost the hover lift that invited the click. And the service icon set was redrawn: the old one reached for the generic metaphor every time — a globe for web work, a lightbulb for consulting, a palette for brand — so four of the six could have swapped places unnoticed. They name the deliverable instead: a rack, a dashboard in a browser chrome, an artboard split into its two themes, a reading taken off a chart, a target with the shot in it, a mark on its swatches.
